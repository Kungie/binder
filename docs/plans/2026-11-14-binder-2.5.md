# Binder 2.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The agent picks up its tasks and night tasks run on the server from 03:00; Binder keeps running with its window closed and watches the server's containers; plus interface size, SD card space, the biggest processes and folders, and a designed DMG window.

**Architecture:** The rules live in the core, pure and tested against `FakeRemote` and an in-memory `Db`: `pickup.rs` (which task, one round), `night.rs` (the server queue, `night.sh`, the crontab line), `watch.rs` (container trouble as alerts), and new reads in `server.rs`. The app runs two background loops (`background.rs`) on `AppState`, hides the window instead of closing it, and sends notifications. The interface adds the night mark, Settings switches, a Display panel, the Server lists and the SD bars through the `Api` interface.

**Tech Stack:** Rust 2024, Tauri 2.12, React 19, TypeScript, Tailwind 4, Vitest. New: `tauri-plugin-notification = "2"` (app).

**Spec:** `docs/specs/2026-11-14-binder-2.5-design.md`

## Global Constraints

- Repo text in English; copy plain, no exclamation marks, no em dashes, no filler. UI copy is exactly the spec's.
- Never commit personal addresses (LAN or Tailscale), host names, serials or keys. Demo data uses `demo-dev` and `10.0.7.x`.
- Every value that reaches a remote shell goes through `remote::quote`. The database is never locked during an SSH call.
- Night colour `#B76EDB`. Pick-up every 10 minutes and 30 s after start; watch every 60 s; three missed checks before `Can't reach the server`. Night jobs start from 03:00, none after 07:00. Interface sizes 100, 110, 125, 150.
- The crontab line is marked `# binder-night`; Remove leaves every other line as it was.
- Build and test only through `make test` and `make build`. Don't run `make install`. Releasing needs the owner's yes.

## Review Focus

1. A task that is both a night task and picked up, or picked up by two rounds: it must start once. (Task 2: `night_tasks_are_never_picked_up`, `nothing_starts_while_a_run_is_live`.)
2. A queued night run polled before 03:00 must stay queued, not end as lost. (Task 3: `a_queued_run_stays_queued_until_it_starts`.)
3. A crontab with other lines, or none at all: Set up adds one line, Remove takes only it out. (Task 3: `cron_install_keeps_other_lines`, `cron_remove_keeps_other_lines`, `cron_install_on_an_empty_crontab`.)
4. A container that was stopped before Binder started, or flaps between states: no alert for the first, one alert per change for the second. (Task 4: `already_stopped_at_start_is_quiet`, `one_alert_per_change`.)
5. The SD card path that isn't a mount of its own (no card): it must not be counted twice in the Disk box. (Task 5: `sd_not_a_mount_is_left_out`.)

### Task 3: The night queue on the server

**Files:**
- Create: `crates/core/src/night.rs`
- Modify: `crates/core/src/agent.rs` (`poll_run` for queued runs), `crates/core/src/pickup.rs` (`round` syncs the queue)
- Test: `crates/core/tests/night.rs`

**Interfaces:**
- Produces:
  - `pub const MARK: &str = "# binder-night";`, `pub const SCRIPT: &str` (the body of `~/.binder-agent/night.sh`).
  - `pub fn cron_state(remote) -> Result<bool>`, `pub fn cron_install(remote) -> Result<()>` (writes `night.sh` with mode 755, adds `0 3 * * * $HOME/.binder-agent/night.sh # binder-night` if absent), `pub fn cron_remove(remote) -> Result<()>`.
  - `pub fn sync(db: &Mutex<Db>, remote, now) -> Result<()>`: each night task in Todo with an agent folder and no queued run gets one (a row with `queued = 1`, its prompt sent on stdin to `~/.binder-agent/night/<run>.job`, the folder and access on the job's first lines, quoted); each queued run whose task is no longer night, no longer Todo, or gone, has its job file removed and its row deleted.
  - `pub fn clear(db: &Mutex<Db>, remote) -> Result<()>`: removes every queued job and its row (used when the crontab line is removed, so nothing waits for a timer that is gone).
  - `poll_run` on a queued run: if `<run>.pid` exists on the server, clear `queued`, set `started = now`, then read it as any run; if the job file is still there, return it unchanged; otherwise it ends as lost.
  - `round` calls `sync` first when `cron_state` is true.
- `night.sh` (POSIX sh): exits unless the hour is 03 to 06; takes `~/.binder-agent/night/*.job` oldest first; for each, moves the job to `<run>.prompt`, `cd` to its folder, writes `.pid`, runs `claude -p <flag> < <run>.prompt > <run>.log 2>&1`, writes `.exit`, and moves on when it ends; checks the hour before each job.
