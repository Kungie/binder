# Binder 1.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Search, import of CLAUDE.md and AGENTS.md, a PreCompact catch, lessons from failed commands, fading, Wrong, expiry, and code summaries.

**Architecture:** New BinderCore units:
- `Search.swift` (BM25 over note lines)
- `Importer.swift` (finds the files, remembers versions, turns lines into proposals)
- `CodeDigest.swift` (builds the model's input from a repo)
- `Forgetting.swift` (fade rules, pins, wrong lines, expiry)

The summarizer gains three prompts: import, code and the review additions. The CLI gains `search`, `import`, `index` and `capture --now`. The UI work is in `NoteView`, `LibraryModel`, `LibraryWindow` and `SettingsView`.

**Tech Stack:** Swift 6 tools in Swift 5 mode, SwiftUI, macOS 14, Swift Testing. No dependencies.

**Spec:** `docs/specs/2026-11-05-binder-1.2-design.md`

## Global Constraints

- Everything Binder shows or writes is English. Every new model prompt says so.
- Every model call runs only with `summarizerConsent`, through `ClaudeCLISummarizer.runner()`. Model output is redacted.
- Every new store (`.binder/imported.json`, `.binder/expiry.json`, pins in `usage.json`) decodes with `decodeIfPresent`. A missing or corrupt file loads empty. Stores keep only paths, hashes and dates.
- Everything new from a file or a session goes through the inbox and Keep.
- Use `make test [FILTER=…]`. Never `@State`.
- Commit after each task, with no attribution lines. Push only when asked.

## Review Focus

1. **A huge CLAUDE.md** (Binder's own is 12 KB), or a repo with 50,000 files. Input caps must hold and the hook must never run the model. Covered by `importCapsAFileAt12k` (Task 7) and `fileListFoldsPastTheCap` (Task 8).
2. **A search query with regex characters or no matches.** It must never crash, and an empty query prints usage. Covered by `oddQueriesAreSafe` (Task 1).
3. **Fading must never hide me.md or access lines, or lines without a date.** Covered by `fadingSparesMeAccessAndUndated` (Task 4).
4. **Wrong on a line with a detail or a kept file.** The detail moves with it and the file stays. Covered by `wrongKeepsDetailAndFile` (Task 5).
5. **Expiry dates in the past, unparseable dates, or dates very far ahead.** Past and unparseable dates are ignored at review time. Covered by `untilMustBeAFutureDate` (Task 6).

### Task 1: Search core and `binder search`

**Files:** Create `Sources/BinderCore/Search.swift`. Modify `Sources/BinderCLI/main.swift` and `Sources/BinderCLI/Commands.swift`. Test: `Tests/BinderCoreTests/SearchTests.swift`.

**Produces:**
- `public struct SearchHit: Equatable, Sendable { public var path: String; public var line: String; public var score: Double }`
- `public enum Search`:
  - `static func run(_ query: String, vault: Vault, project: String? = nil, includeSuperseded: Bool = false, limit: Int = 12) -> [SearchHit]`
  - `static func render(_ hits: [SearchHit], budget: Int = 1_500) -> String`
- **Documents:** every line of every note from `UsageHandles.notes(vault:)`:
  - decision items, with details joined in;
  - observed lines;
  - free lines.
  Superseded lines count only with `includeSuperseded`.
- **Scoring:**
  - BM25 with k1 = 1.2 and b = 0.75, over lowercased alphanumeric tokens.
  - +2 when the whole query appears as a phrase.
  - ×1.5 for paths under `projects/<project>` or `projects/<project>.md`.
- **CLI:** `binder search <words…> [--project p] [--all] [--limit n]` prints `render` and records `UsageStore.recordSearch(hits:)`, which counts `used` once per hit line and note. An empty query prints usage and exits 2.
