# Binder 2, part 2: server, devices, repos, agent, printer, done hook

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish Binder 2: the Server and Devices screens, repo status on projects, agent runs on the Pi, the Bambu printer, and done lines written from Claude Code sessions.

**Architecture:**
- **Core.** Everything that talks to the outside goes through a small trait, so `crates/core` stays testable with fakes:
  - `Remote` for SSH;
  - `Git` for repo status;
  - `Summarizer` for `claude -p`.
- **Printer.** The printer's MQTT client lives in the Tauri app, because it's a long-lived connection. Its report parsing and command payloads live in the core.
- **Hook binary.** A new crate `crates/cli` builds `binder-cli`, which Claude Code's hooks call. It ships inside `Binder.app` as a Tauri sidecar.

**Tech Stack:**
- Additions to part 1: `rumqttc` with `rustls` (MQTT over TLS), `sha2`, `keyring` (the macOS Keychain), `regex`.
- Everything else stays as in part 1.

**Spec:** `docs/specs/2026-11-13-binder-2-design.md`, sections 3, 6, 7, 8 and 9, plus the repo line under Projects. The spec was updated on 2026-11-13 so agent runs use `setsid nohup` instead of tmux.

## Global Constraints

- **Part 1 rules hold:** English everywhere, the black-and-white tokens, weights 400 and 500, builds through `make` with `CARGO_TARGET_DIR` outside iCloud, nothing personal in the repo, no push without asking.
- **SSH:**
  - Always `ssh -o BatchMode=yes -o ConnectTimeout=5 <target>`. Binder never reads or writes `~/.ssh` and never installs anything on the Pi.
  - The target comes from `config.toml` (for example `server = "user@host"`), never from the repo.
- **Polling:** the server every 30 s and live agent runs every 10 s, only while the window is visible (`document.visibilityState`).
- **Devices:** online is a TCP connect with a 2 s timeout to port 22, or the device's own port.
- **Printer:**
  - MQTT over TLS on 8883, user `bblp`.
  - The access code lives in the Keychain (service `io.github.kungie.binder.printer`, account the serial) and never in a file, a log or the UI.
  - The certificate is pinned by SHA-256 on first connect, and a different one is refused.
- **Done hook:**
  - Hooks `Stop`, `PreCompact` and `SessionEnd`. `Stop` only counts; summarizing starts at 4,000 characters, or on `PreCompact` or `SessionEnd`.
  - At most 3 lines per call. The model sees the last 20 done lines.
  - Secrets are redacted before the model sees anything.
  - The hook returns within 1 s and leaves the model call to a detached `binder-cli summarize` process.
  - `claude -p` runs bare:
    - flags `--model haiku`, `--tools ""`, `--strict-mcp-config`, `--setting-sources ""`, `--disable-slash-commands` and `--no-session-persistence`;
    - from an empty scratch folder, on the owner's plan, with no API key.

## Review Focus

1. A server that answers slowly or not at all: the Server screen shows "Can't reach <target>" with the time of the last good read. The window never freezes, because every SSH call runs off the main thread with the 5 s connect timeout. Tests are in Tasks 2 and 4.
2. Shell quoting: an agent folder or prompt with spaces, quotes, `$` or backticks must reach the Pi as data, never as a command. Tests are in Task 5.
3. Bambu reports are partial deltas. A report with only `mc_percent` must not erase the temperatures. Tests are in Task 7.
4. Two Claude Code sessions in one project, or a transcript that was rewritten: each byte is read once, and a cursor past the end of the file starts over at 0. Tests are in Task 9.
5. The vault is unmounted when a done line is due: the line waits in `pending_done` and is written on the next hook or app start, never lost and never written twice. Tests are in Task 9.

### Task 5: Agent runs in the core

**Files:**
- Create: `crates/core/src/agent.rs`, `crates/core/tests/agent.rs`.

**Interfaces (produces):**
- **Records:**
  - `Access { EditsOnly, Full }`
  - `AgentRun { id, task_id, run, dir, access, started, ended: Option<i64>, exit_code: Option<i32>, tail: String }`
  - `RunState { Running, Exited(i32), Lost }`
- **`start_run(db, remote, task_id, dir, access, now) -> Result<AgentRun>`:**
  - The run id is `<task key>-<unix time>`, lowercased.
  - The prompt is the task title, a blank line, then the notes.
  - It sends this script, with the prompt on stdin:
    ```
    mkdir -p ~/.binder-agent && cat > ~/.binder-agent/<run>.prompt
    command -v claude >/dev/null || { echo "Claude Code isn't installed on this server." >&2; exit 3; }
    cd <quoted dir> && setsid nohup sh -c 'claude -p <mode> < ~/.binder-agent/<run>.prompt > ~/.binder-agent/<run>.log 2>&1; echo $? > ~/.binder-agent/<run>.exit' >/dev/null 2>&1 & echo $! > ~/.binder-agent/<run>.pid
    ```
  - `<mode>` is `--permission-mode acceptEdits`, or `--dangerously-skip-permissions` for `Full`.
  - It sets the task to in progress.
  - The script runs through `sh -lc`, so `~/.local/bin` is on the PATH.
- **`poll_run(db, remote, run_id, now) -> Result<AgentRun>`:**
  - One call reads the exit file, checks the pid with `kill -0`, and reads `tail -n 40` of the log.
  - Exit 0 sets the task to done. Any other exit sets it back to todo and keeps the tail. A dead pid with no exit file is `Lost`, and the task goes back to todo.
- **`stop_run`:** `kill -- -<pid>`. The run ends with exit code 143.

### Task 9: Done lines from sessions in the core

**Files:**
- Create: `crates/core/src/session.rs`, `crates/core/src/redact.rs`, `crates/core/tests/session.rs`, `crates/core/tests/fixtures/transcripts/*.jsonl` (made-up).

**Interfaces (produces):**
- **Input:**
  - `HookInput { session_id, transcript_path, cwd, hook_event_name }` (serde).
  - `pub fn project_for(db, cwd) -> Option<Project>` matches the longest repo folder that contains `cwd`.
- **`pub fn new_talk(path, offset) -> Result<(String, u64)>`:**
  - It reads the user and assistant text blocks after `offset`, as `User: …` and `Assistant: …` lines, and skips tool calls and results.
  - An `offset` past the end of the file starts over at 0.
- **`pub fn on_hook(db, input, now) -> Result<HookAction>`:**
  - `HookAction` is `Nothing` or `Summarize { session_id }`.
  - `Stop` adds to `pending_chars`, and asks to summarize at 4,000 or more. `PreCompact` and `SessionEnd` ask whenever any talk is waiting.
- **`pub trait Summarizer { fn lines(&self, done: &[String], talk: &str) -> Result<Vec<String>>; }`**
  - `ClaudeSummarizer` runs the bare `claude -p` from Global Constraints. The prompt asks for at most 3 English one-line key decisions as JSON `{"lines": [...]}`, or none.
  - `parse_lines(&str) -> Vec<String>` takes the first JSON object in the output.
- **`pub fn summarize(db, vault, summarizer, session_id, today) -> Result<usize>`:**
  - It claims the talk (moving the cursor first, so each byte is read once), redacts it, and keeps the last 12,000 characters.
  - It calls the summarizer and drops lines whose normalized text is already in the log.
  - It appends the rest, or queues them in `pending_done` when the vault is missing.
- **`pub fn flush_pending(db, vault) -> Result<usize>`.**
- **`redact(&str) -> String`** masks:
  - `sk-…` and `ghp_…`/`gho_…` tokens;
  - `AKIA…` keys;
  - `-----BEGIN … PRIVATE KEY-----` blocks;
  - `password=…`, `token: …` and `Bearer …` values;
  - any run of 40 or more base64 or hex characters.
