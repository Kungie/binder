# Binder 2.7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A morning brief on Overview, GitHub issues as tasks with PR counts and CI, container logs and restart, print notifications, a Sites screen, a weekly note in the vault, a fuller New task, and the 3D Printer name.

**Architecture:** The rules live in the core, pure and tested against `FakeRemote`, a fake `GitHub` and an in-memory `Db`. New core files: `events.rs` (the event log), `brief.rs`, `sites.rs`, `weekly.rs`; `github.rs`, `server.rs`, `watch.rs` and `printer.rs` grow. The app wires them into `background.rs`, the printer worker and new commands; the interface adds the brief card, the Sites screen, the container panel and the new dialog through the `Api` interface, mirrored in `memory.ts`.

**Tech Stack:** Rust 2024, Tauri 2, React 19, TypeScript, Tailwind 4, Vitest. No new crates: the site check runs the system `/usr/bin/curl`.

**Spec:** `docs/specs/2026-11-15-binder-2.7-design.md`

## Global Constraints

- Repo text in English; copy plain, no exclamation marks, no em dashes, no filler. UI copy is exactly the spec's.
- Never commit personal addresses, host names, serials or keys. Demo data uses `demo-dev` and `10.0.7.x`; demo sites use `example.com` names.
- Every value that reaches a remote shell goes through `remote::quote`. The database is never locked during an SSH or `gh` call.
- Site discovery reads only `hostname:` lines of `cloudflared/config.yml`, never whole files, tokens, credentials or `.env` files.
- Brief window 05:00 to 12:00 local; brief covers since the last dismiss, else 24 h. Gap 5 minutes. Logs `--tail 200`. Site check 5 s, status below 500. Sites figures every 30 s. Weekly notes up to 4 weeks back; events kept 35 days. Preview 1280 × 800. Dialog 560 px.
- Meaning colours from `CLAUDE.md`: Passing `#4CB782`, Failing `#EB5757`, Running `#F2C94C`.
- Build and test only through `make test` and `make build`. Don't run `make install`. Releasing needs the owner's yes.

## Review Focus

1. A Mac that slept through the night: the brief must still show a container that stopped and came back, and a server reboot, from the server's own times, once each. (Task 4: `a_gap_reads_what_the_server_remembers`, `the_same_gap_is_not_logged_twice`.)
2. A restart the owner starts: no alert from the live watch and none from a later catch-up. (Task 4: `an_owner_restart_is_quiet`; Task 9: `restart_logs_it_as_yours`.)
3. An issue task the owner edited, moved or deleted: sync must not overwrite it or bring it back. (Task 6: `sync_never_overwrites_an_issue_task`, `a_deleted_issue_task_stays_deleted`.)
4. `gh` failing halfway (issues call fails, repos worked): nothing is closed because the list came back empty. (Task 6: `a_failed_issue_read_closes_nothing`.)
5. A weekly note whose file already exists, or a vault that isn't mounted: never overwritten, written later for its own week. (Task 11: `an_existing_note_is_kept`, `without_the_vault_it_waits`.)
