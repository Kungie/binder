# Binder 2.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix what the owner found in 2.1: deleted GitHub projects come back, Cloud is too weak, priority is invisible, the Tasks header has project tabs, Claude Code sessions never reach the vault, and the Server screen shows too many services and a raw load.

**Architecture:** Core logic stays in `crates/core` (no Tauri), behind traits so tests stand in fakes: `GitHub` for sync, a new `Shell` for streaming commands on the server (tests run them locally with `sh`). Tauri commands stay thin. The interface talks to `Api`, with the in-memory fake in `app/src/lib/memory.ts` / `memoryCloud.ts` kept complete.

**Tech Stack:** Rust 2024, rusqlite, Tauri 2, React 19, TypeScript, Tailwind 4, Vitest. New: `zip` crate (core), `tauri-plugin-drag` + `@crabnebula/tauri-plugin-drag`, `objc2-app-kit` (app, macOS).

**Spec:** `docs/specs/2026-11-13-binder-2.2-design.md`

## Global Constraints

- Repo text in English; copy plain, no exclamation marks, no em dashes, no filler.
- Never commit personal addresses (192.168.x, 100.79.x), host names, serials or keys. Demo data uses `demo-dev` and `10.0.7.x`.
- Every Cloud command refuses unless the share is mounted (`mounted()` in `commands.rs`); paths go through `cloud::resolve` first; nothing is deleted outright except Binder's own partials, `.binder-check` and emptying the trash.
- Every shell command built from a path uses `remote::quote`. Nothing else from the interface reaches a shell.
- Look: colour only where it means something; menus `raised` (`#242428`) with 8 px radius and 1 px `line-strong` border; chips 24 px pills; Geist Mono for paths and numbers.
- Build and test only through `make test` (it sets `CARGO_TARGET_DIR=$HOME/Library/Caches/Binder/target`). Don't run `make install`.
- Commits small, on `binder-2.2`, no attribution lines. Never push or merge without asking.

## Review Focus

1. Names with spaces, quotes, `$`, backticks, a leading `-` or non-ASCII in every fast-path operation: the right file is touched, nothing else runs. (Task 8 test `awkward_names_survive_every_fast_op`.)
2. The mount not yet seeing a partial the server just finished: landing it over SMB must wait briefly, not fail. (Task 7 test `land_waits_for_a_partial_the_share_hasnt_shown_yet`.)
3. Pasting or moving a folder into itself or its own subfolder, through copy, duplicate or the fast path: refused before anything runs. (Task 8 test `copy_into_itself_is_refused`.)
4. Lines queued while the vault was away are flushed into their own day's daily file, not today's. (Task 4 test `pending_lines_land_in_their_own_day`.)
5. A hidden repo with a hand-added project of the same name: the project stays unlinked. (Task 1 test `hidden_repo_is_not_linked_by_name`.)

### Task 8: Cloud fast path over SSH (core)

**Files:**
- Create: `crates/core/src/shell.rs`, `crates/core/src/cloud_fast.rs`
- Modify: `crates/core/src/lib.rs`, `crates/core/src/config.rs` (`cloud_remote: String`, default `"/srv/cloud"`)
- Test: `crates/core/tests/cloud_fast.rs` (new), `crates/core/tests/config.rs`

**Interfaces:**
- Produces (`shell.rs`):
  - `pub trait Shell: Send + Sync { fn spawn(&self, script: &str) -> Result<std::process::Child>; }` with stdin, stdout and stderr piped.
  - `pub struct SshShell { pub target: String, pub program: String }` running `ssh -o BatchMode=yes -o ConnectTimeout=5 -o ServerAliveInterval=5 -o ServerAliveCountMax=2 -- <target> sh -c <quoted script>`.
  - `pub struct LocalShell;` running `sh -c <script>` (tests, and nothing else).
  - `pub fn run(shell: &dyn Shell, script: &str) -> Result<String>`: waits, returns stdout or `Error::Remote(stderr)`.
- Produces (`cloud_fast.rs`): `pub struct Fast<'a> { pub shell: &'a dyn Shell, pub root: &'a Path, pub remote_root: &'a str, pub gnu_tar: bool }` with:
  - `pub fn check(&self) -> bool`: writes a random token to `<root>/.binder-check` over the mount, `cat`s `<remote_root>/.binder-check` over the shell, removes the file, true when equal.
  - `pub fn remote(&self, rel: &str) -> Result<String>`: `resolve` on the mount first, then `remote_root + "/" + normalised rel`.
  - `upload_dir(&self, src: &Path, dst_rel: &str, conflict, cancel, progress) -> Result<Option<PathBuf>>`: Mac `COPYFILE_DISABLE=1 /usr/bin/tar --no-mac-metadata --no-xattrs -cf - -C <src> .`, Rust pumps its stdout into the shell's stdin for `mkdir <partial> && tar --warning=no-unknown-keyword -xf - -C <partial>`, progress in bytes against `tree_size` of the source; then `cloud::land` over the mount.
  - `download_dir(&self, rel, dst_dir: &Path, conflict, cancel, progress) -> Result<Option<PathBuf>>`: the reverse, total from `du -sb` on the server, landing with `trash_root: None`.
  - `copy(&self, rel, dst_dir_rel, name: &str, conflict, cancel, progress) -> Result<Option<PathBuf>>`: `cp -a <src> <partial>` then land. Refuses when the destination is the source or inside it.
  - `extract(&self, rel, cancel, progress) -> Result<PathBuf>`: `unzip -Z1` first (refuse absolute or `..` names, total = line count), then `mkdir <partial> && unzip -o <zip> -d <partial>`, counting `inflating:`, `extracting:`, `creating:` and `linking:` lines; land as the zip's stem (free name).
  - `compress(&self, rels: &[String], cancel, progress) -> Result<PathBuf>`: `cd <parent> && zip -r -y <partial> ./<name>…`, total from `find … | wc -l`, counting `adding:` lines; land as in Task 7.
  - `size(&self, rel) -> Result<(u64, u64)>`: `du -sb` and `find | wc -l`.
