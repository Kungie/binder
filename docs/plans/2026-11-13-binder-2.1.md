# Binder 2.1: GitHub projects, task board, colour and Cloud

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 2.1 as the spec describes:
- projects brought in from GitHub and kept in sync;
- a Roma-style task board;
- a tighter look with meaningful colour;
- a Cloud file manager over an SMB share on the home server.

**Architecture:**
- **Core:**
  - GitHub goes through a `GitHub` trait (`GhCli` in the app, a fake in tests), like `Remote`.
  - Cloud file operations are plain filesystem code on the mounted share, in `crates/core/src/cloud.rs`, confined to one root folder.
- **App:**
  - Long copies run on their own threads in the Tauri app and report through events.
  - The board is a new React component beside the existing table; both read the same store.

**Tech Stack:**
- Additions: `libc` (`statvfs` for free space).
- Everything else stays as in 2.0. Drag and drop uses native HTML drag events, and Tauri's window drag-drop event for files from Finder.

**Spec:** `docs/specs/2026-11-13-binder-2.1-design.md` (the 2.0 spec holds where it is silent).

## Global Constraints

- **2.0 rules hold:**
  - English in the repo.
  - Inter 400/500 and Geist Mono.
  - Builds through `make`.
  - Nothing personal committed. Demo data uses a made-up developer, `10.0.7.x` and made-up repos.
  - No push without asking.
- **Tokens (exact values):**
  - Surfaces: bg `#0B0B0C`, panel `#141416`, card `#1C1C1F`, raised `#242428`, line `#26262A`.
  - Status colours: backlog/canceled `#6B6B6B`, todo `#D4D4D4`, in progress `#F2C94C`, done `#8B7CF6`.
  - Other meanings: urgent and attention `#F2994A`, error and offline `#EB5757`, online and running `#4CB782`.
  - Project palette: `#5E6AD2 #26B5CE #4CB782 #F2C94C #F2994A #EB5757 #B76EDB #8D8D8D`.
- **Colour is small:** only on icons, dots, chip icons, 2 px bars and overdue chip text. Surfaces stay neutral.
- **Shape:** radius 10 px on cards and panels, 8 px on controls. Chips are pills 24 px high. Sidebar 208 px; detail screens max 960 px; 8 px spacing grid.
- **GitHub:** only through the `gh` CLI's own login. Binder never reads, asks for or stores a token. `gh` is found on the PATH, then in `/opt/homebrew/bin` and `/usr/local/bin`.
- **Sync never overwrites the owner's edits:**
  - Preserved: name, state, prefix, colour, local folder, agent folder.
  - Never deleted: projects. Gone or archived repos are marked `archived`.
- **Cloud:**
  - Every path is relative to the configured root, and any path that resolves outside it is refused.
  - Delete always moves to `<root>/.trash/`.
  - Copies run in 1 MB chunks off the main thread, and a cancelled copy removes its partial file.
- **Config:**
  - `cloud` (default `/Volumes/cloud`) and `cloud_share` (default none) live in `config.toml`.
  - The owner's share URL is never committed.

## Review Focus

1. **Cloud paths that try to leave the root:** `../x`, `/etc`, an encoded `..`, or a symlink inside the share pointing outside. Each is refused with an error, never followed. The tests are in Task 4.
2. **A large copy that is cancelled or fails halfway** leaves no partial file and no frozen window. The tests are in Tasks 4 and 5.
3. **Fourteen repos arriving in one sync:**
   - unique prefixes;
   - the owner's renamed project not renamed back;
   - a hand-made project with the same name linked, not duplicated;
   - an archived repo marked, never deleted.

   The tests are in Task 2.
4. **Name conflicts on upload and restore:** "Keep both" makes `photo 2.jpg`, not `photo.jpg 2`, and a folder conflict makes `Folder 2`. The tests are in Task 4.
5. **Board drag:** dropping on Done shows the done-line prompt once. Reordering inside a column never changes status or shows the prompt. The tests are in Task 7.

### Task 2: GitHub sync in the core

**Files:**
- Create: `crates/core/src/github.rs`, `crates/core/tests/github.rs`

**Interfaces (produces):**
- **`Repo`**: `{ name, name_with_owner, description: Option<String>, url, is_private, is_archived, pushed_at: String, language: Option<String> }`. It deserializes from `gh`'s JSON, with camelCase renames.
- **`trait GitHub { fn login(&self) -> Result<String>; fn repos(&self, login: &str) -> Result<Vec<Repo>>; }`**
- **`GhCli { program: PathBuf }`**:
  - `GhCli::find() -> Option<GhCli>`.
  - `repos` runs `gh repo list <login> --limit 200 --json name,nameWithOwner,description,url,isPrivate,isArchived,pushedAt,primaryLanguage`.
  - A non-zero exit becomes `Error::Invalid("Sign in with gh auth login to bring in your GitHub repos.")` when stderr mentions auth; otherwise the trimmed stderr.
- **`pub fn sync(db: &mut Db, gh: &dyn GitHub, now: i64) -> Result<SyncReport>`**, with `SyncReport { added, linked, updated, archived }` (`usize`).
  - **A new repo** becomes a project:
    - name = repo name, prefix derived as 2.0;
    - `active` if pushed within 60 days of `now`, else `paused`;
    - `color_for(name)`.
  - **A hand project with the same name** (case-insensitive) and no `github` gets linked.
  - **A known repo** updates only `url`, `description`, `private`, `pushed_at` and `archived`.
  - **A project whose repo is missing from the list** gets `archived = true`.
  - **Everything runs in one transaction.**

### Task 4: Cloud in the core

**Files:**
- Create: `crates/core/src/cloud.rs`, `crates/core/tests/cloud.rs`

**Interfaces (produces):**
- **Records:**
  - `Entry { name, rel: String, kind: Kind { File, Dir, Link }, size: u64, modified: i64 }`
  - `Conflict { Replace, KeepBoth, Skip }`
  - `Space { total: u64, free: u64 }`
- **`pub fn resolve(root: &Path, rel: &str) -> Result<PathBuf>`:**
  - It joins without touching the disk, rejects absolute paths and any `..` component, then canonicalizes the parent and checks it is under the canonical root.
  - It fails with `Error::Invalid("That path is outside Cloud.")`.
- **Browsing:**
  - `pub fn list(root, rel, show_hidden: bool) -> Result<Vec<Entry>>`: folders first, then name (case-insensitive). It never lists `.trash`, and hides dotfiles unless asked.
- **Copying:**
  - `pub fn free_name(dir: &Path, name: &str) -> PathBuf`: `name 2.ext`, `name 3.ext` and so on. Folders and extensionless names get `name 2`.
  - `pub fn copy_into(src: &Path, dst_dir: &Path, conflict: Conflict, cancel: &AtomicBool, progress: &mut dyn FnMut(u64, u64)) -> Result<Option<PathBuf>>`:
    - copies a file or a folder recursively, in 1 MB chunks;
    - reports `(done_bytes, total_bytes)`;
    - returns `None` on `Skip`;
    - on cancel or error, removes what it wrote and returns `Err(Error::Invalid("Cancelled."))` or the IO error.
- **Managing:**
  - `pub fn mkdir(root, rel_dir, name)`, `rename(root, rel, new_name)` and `move_to(root, rel, dest_dir_rel)`. A name may not contain `/` or be `.`/`..`.
- **Trash:**
  - `pub fn trash(root, rel) -> Result<()>`: moves to `.trash/<rel>`, using `free_name` on a clash inside the trash.
  - `list_trash(root) -> Result<Vec<Entry>>`: the top-level items, with `rel` relative to `.trash`.
  - `restore(root, trash_rel) -> Result<PathBuf>`: moves back to the same relative path, recreating missing parents, using `free_name` on a clash.
  - `empty_trash(root) -> Result<()>`.
- **Space:**
  - `pub fn space(root: &Path) -> Result<Space>`: uses `statvfs`.

  - a `mounted` option;
  - uploads that finish after two fake progress events.
