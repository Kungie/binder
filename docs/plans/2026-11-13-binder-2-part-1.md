# Binder 2, part 1: shell, tasks, projects and notes

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Swift app with a Tauri app that has the black-and-white shell, the task table, projects with Obsidian notes on the Pi, and an Overview.

**Architecture:**
- **Rust core.** `crates/core` owns the SQLite database, tasks, projects, the config file and the note files. It has no Tauri dependency and is tested with `cargo test`.
- **Tauri app.** `app/src-tauri` exposes thin commands over the core.
- **React UI.** `app/src` talks to an `Api` interface. That interface has two implementations: Tauri `invoke` in the app, and an in-memory fake used by Vitest and by the browser preview.

**Tech Stack:**
- Rust 1.99: rusqlite (bundled), serde, serde_json, toml, chrono, thiserror; tempfile for tests.
- Tauri 2 with plugin-opener and plugin-dialog.
- Node 26 with npm: Vite, React 19, TypeScript, Tailwind 4, cmdk, Vitest, Testing Library and jsdom.
- Fonts from @fontsource/inter and @fontsource/geist-mono.

**Spec:** `docs/specs/2026-11-13-binder-2-design.md` (sections 1 to 5a, 10 and Testing; the other sections are later parts).

## Global Constraints

- Everything in the repo and the UI is English. Copy has no exclamation marks, no em dashes and no filler.
- **Look:** dark only, no colour. The tokens are exactly `bg #000000`, `panel #0A0A0A`, `raised #141414`, `line #1C1C1C`, `line-strong #2A2A2A`, `text #EDEDED`, `text-2 #A1A1A1`, `text-3 #6B6B6B`. The primary button is an `#EDEDED` fill with `#000000` text, one per view.
- **Type and shape:** Inter at 13 px (12 px in tables), weights 400 and 500 only. Geist Mono for numbers, ids and paths. Radius 6 px on controls and 8 px on panels, 1 px hairlines. Shadows only on menus and the palette. 120 ms motion, none with `prefers-reduced-motion`.
- **Locations:**
  - Data in `~/Library/Application Support/io.github.kungie.binder/`: `binder.db` and `config.toml`.
  - Bundle id `io.github.kungie.binder`, product name `Binder`.
- **Vault:** the default path is `/Volumes/vault`. Binder only appends under `## Done` and never writes anywhere else in a note. Nothing is written when the vault folder is missing.
- **Build output:** `~/Desktop` syncs with iCloud, which breaks codesign on build output. The Makefile exports `CARGO_TARGET_DIR=$(HOME)/Library/Caches/Binder/target`, and every build goes through `make`.
- **Public repo:** nothing personal is committed: no addresses, host names or serials. Demo data uses a made-up developer and `10.0.7.x` addresses.
- **Git:** commit after each task, with no attribution lines. Never push without the owner's go-ahead.

## Review Focus

1. A note whose `## Done` is followed by other sections, or that has no `## Done`, or that uses CRLF line endings: the new line lands at the end of the Done section, and every other byte stays as it was. Tests are in Task 4.
2. A project name with `/`, `:`, `#` or Turkish letters (`Şirket ağı`): the note's file name is safe, and the `obsidian://` URL is percent-encoded UTF-8. Tests are in Task 4.
3. The vault isn't mounted: Start project and logging return `Error::VaultMissing`, the UI shows "Vault not connected", and nothing is written. Tests are in Tasks 4 and 8.
4. Deleting a project that has tasks: the tasks stay, keep their keys and lose the project. Two tasks created back to back never share a key. Tests are in Tasks 2 and 3.
5. Done text that is empty, only spaces or several lines: empty is skipped, several lines become one. Tests are in Task 4.

### Task 2: Models, database and tasks

**Files:**
- Create: `crates/core/src/model.rs`, `crates/core/src/db.rs`, `crates/core/src/tasks.rs`, `crates/core/tests/tasks.rs`.

**Interfaces:**
- Produces, all serde, with enums in `snake_case`:
  - **Enums:**
    - `Status { Backlog, Todo, InProgress, Done, Canceled }`
    - `Priority { None, Low, Medium, High, Urgent }`, stored as 0 to 4
    - `Assignee { Me, Agent }`
    - `ProjectState { Active, Paused, Done }`
  - **`Task`:** `{ id: i64, key: String, title: String, notes: String, status, priority, project_id: Option<i64>, assignee, due: Option<String> /* YYYY-MM-DD */, created: i64, updated: i64 }` (unix seconds).
  - **`NewTask`:** `{ title: String, notes, status, priority, project_id, assignee, due }`. Every field but `title` is optional. The defaults are `""`, `Todo`, `None`, no project, `Me`, no due date.
  - **`TaskPatch`:** every field optional, plus `clear_project: bool` and `clear_due: bool`.
  - **`TaskView`:** `All | Mine | Agent | Project(i64)`, serde `tag = "kind", content = "id"`.
  - **`Db`:** `Db::open(&Path) -> Result<Db>` and `Db::in_memory() -> Result<Db>`. Migrations run through `PRAGMA user_version`, and `foreign_keys` is on.
  - **Task methods on `Db`:**
    - `create_task(&mut self, NewTask, now: i64) -> Result<Task>`
    - `get_task(&self, id) -> Result<Task>`
    - `list_tasks(&self, TaskView, include_closed: bool) -> Result<Vec<Task>>`
    - `update_task(&mut self, id, TaskPatch, now) -> Result<Task>`
    - `delete_task(&mut self, id) -> Result<()>`

**Schema v1:**
- `projects(id, name UNIQUE, prefix UNIQUE, repo, note, state, next_number DEFAULT 1, created)`
- `tasks(id, key UNIQUE, title, notes, status, priority, project_id REFERENCES projects ON DELETE SET NULL, assignee, due, created, updated)`
- `counters(name PRIMARY KEY, next)`

**Keys:**
- With a project, a key is the project's `prefix-next_number`. Without one, it's `TSK-n` from `counters`.
- The counter goes up in the same transaction that inserts the task.
- A key never changes, even when the task moves to another project.

**List order:**
- Status rank first: in progress, todo, backlog, done, canceled.
- Then priority: urgent, high, medium, low, none.
- Then `updated`, newest first.
- `include_closed = false` leaves out done and canceled.

### Task 4: Notes and config

**Files:**
- Create: `crates/core/src/notes.rs`, `crates/core/src/config.rs`, `crates/core/tests/notes.rs`, `crates/core/tests/config.rs`.

**Interfaces:**
- Consumes: `Project` from Task 3.
- Produces:
  - **`DoneLine { date: String, text: String }`** (serde).
  - **`note_path(vault: &Path, project_name: &str) -> PathBuf`**
    - Builds `vault/Projects/<safe>.md`.
    - `safe` replaces each of `/ \ : * ? " < > | # ^ [ ]` with `-`, collapses runs of spaces and dashes, and trims. An empty result becomes `Untitled`. Turkish and other letters stay.
  - **`ensure_note(vault: &Path, p: &Project, today: &str) -> Result<(PathBuf, bool)>`**
    - Returns `Error::VaultMissing(vault)` when `vault` isn't a directory.
    - Otherwise it creates `Projects/` if needed and writes the template when the file doesn't exist. The `bool` is true when it created the note. An existing file is never changed.
  - **`append_done(path: &Path, date: &str, text: &str) -> Result<bool>`**
    - Returns `VaultMissing` when the note's vault folder (two levels up) is missing.
    - Returns `false` and writes nothing when `one_line(text)` is `None`.
  - **`read_done(path) -> Result<Vec<DoneLine>>`**: oldest first. A missing file gives an empty list, and lines in the section that don't match are skipped.
  - **`one_line(text) -> Option<String>`**: collapses all whitespace, newlines included, to single spaces and trims. Empty gives `None`. The result is cut to 200 characters on a character boundary.
  - **`obsidian_url(path) -> String`**: `obsidian://open?path=` plus the absolute path, percent-encoded as UTF-8 bytes. Only `A-Z a-z 0-9 - _ . ~ /` stay as they are.
  - **`done_on(projects: &[Project], day: &str) -> Vec<(String, DoneLine)>`**: reads each project's `note` and returns the lines for that day with the project's name. Unreadable notes are skipped.
  - **`Config { vault: PathBuf }`** (serde):
    - `Config::load(path: &Path) -> Result<Config>`: a missing file gives `vault = /Volumes/vault`.
    - `Config::save(&self, path) -> Result<()>`: creates parent folders.

**Note template** (exactly; `repo:` is empty when there is none):
```
---
project: <name>
repo: <repo>
started: <today>
---

# <name>

## Done
```

**`append_done` placement:**
- The line is `- <date> · <one_line(text)>`.
- It goes after the last non-blank line of the `## Done` section. The section starts at a line that trims to `## Done` and ends at the next line starting with `#`, or at the end of the file.
- When there's no `## Done` section, `\n## Done\n<line>\n` is added at the end, after first making sure the file ends with a newline.
- The file's line ending (CRLF if it contains `\r\n`, else LF) is used for the inserted text.
