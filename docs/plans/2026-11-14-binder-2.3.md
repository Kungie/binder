# Binder 2.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Agents screen with two live terminals into tmux sessions on the home server (Claude Code left, Qwen3 4B right), and a Power box on the Server screen.

**Architecture:** The core builds the `ssh` command lines and parses power (pure, tested). The app side owns pseudo-terminals running the Mac's own `ssh -tt`, streams their bytes to the window over a Tauri `Channel`, and kills them on quit. The interface draws them with xterm.js inside a thin `XtermView`, wrapped by a `Terminal` panel that owns state and keyboard isolation, so tests swap `XtermView` for a textarea.

**Tech Stack:** Rust 2024, Tauri 2, React 19, TypeScript, Tailwind 4, Vitest. New: `portable-pty = "0.9"` (app), `@xterm/xterm@5.5.0`, `@xterm/addon-fit@0.10.0`, `@xterm/addon-clipboard@0.1.0` (interface).

**Spec:** `docs/specs/2026-11-14-binder-2.3-design.md`

## Global Constraints

- Repo text in English; copy plain, no exclamation marks, no em dashes, no filler.
- Never commit personal addresses (192.168.x, 100.79.x), host names, serials or keys. Demo data uses `demo-dev` and `10.0.7.x`.
- Binder holds no key, token or password and never touches `~/.ssh`; it runs the system `ssh` with `-o BatchMode=yes`.
- The server target goes into the `ssh` command only as one argv element; anything that reaches the remote shell is built with `remote::quote`.
- Session names are fixed: `binder-claude`, `binder-qwen`.
- Quitting Binder or leaving the screen never ends a tmux session; it only ends local `ssh` processes.
- Terminal look: background `#141416`, text and cursor `#EDEDED`, selection `#242428`, Geist Mono 12 px, line height 1.3.
- Build and test only through `make test` (it sets `CARGO_TARGET_DIR=$HOME/Library/Caches/Binder/target`). Don't run `make install`.

## Review Focus

1. Binder quits, or the window closes, while both terminals are connected: no `ssh` process is left running on the Mac. (Task 3: `drop_kills_children`.)
2. Reconnect pressed, or Agents opened again, while a terminal is still connected: the running one is reused, never a second `ssh`. (Task 3: `open_twice_reuses`.)
3. Output that splits a multi-byte character across reads (Turkish letters, box-drawing, Claude's spinner): bytes reach xterm unchanged, never decoded lossily in Rust. (Task 3: `bytes_pass_through_unchanged`.)
4. A server target with a space or a quote (`me@my host`, an alias with `'`): it stays one argv element and the remote command stays intact. (Task 2: `target_is_one_argument`.)
5. Typing `c`, arrows, Escape or Enter in a terminal: no Binder shortcut fires; ⌘K still opens the palette. (Task 5: `terminal_keeps_keys_but_palette_opens`.)

**Interfaces:**
- Consumes: `Agent`, `ssh_args`, `exit_message` (Task 2); `server_target(&State) -> Res<String>` (existing).
- Produces:
  - `pub struct Terminals` (`Default`), with
    - `pub fn open(&self, agent: Agent, program: &str, args: &[String], cols: u16, rows: u16, on_bytes: impl Fn(Vec<u8>) + Send + 'static, on_exit: impl FnOnce(String) + Send + 'static) -> Result<bool, String>`: starts the child unless one is running for `agent`; returns `true` when it started a new one, `false` when it reused (the caller then only swaps its output sink, below).
    - `pub fn write(&self, agent: Agent, data: &[u8]) -> Result<(), String>`, `pub fn resize(&self, agent: Agent, cols: u16, rows: u16) -> Result<(), String>` (unknown agent: `Ok(())`), `pub fn close(&self, agent: Agent)`, `pub fn close_all(&self)`; `Drop` calls `close_all`.

  - Event `term-exit` with payload `{ agent: "claude" | "qwen", message: string }`.

- [ ] **Step 1: Write the failing tests** (they run `/bin/sh`, not ssh):

```rust
#[test]
fn bytes_pass_through_unchanged() // child: sh -c "printf 'g\303'; sleep 0.1; printf '\274l'"; collected bytes == "gül".as_bytes()
#[test]
fn write_reaches_the_child() // child: sh -c 'read x; printf "got:%s" "$x"'; write(b"hi\r"); output ends with "got:hi"
#[test]
fn open_twice_reuses() // open(...) == Ok(true), second open for the same agent == Ok(false), and only one child pid exists
#[test]
fn exit_reports_message() // child: sh -c 'exit 127'; on_exit receives exit_message(Some(127), ..)
#[test]
fn drop_kills_children() // child: sleep 30; drop the Terminals; within 2 s, kill(pid, 0) fails (process gone)
```

Each test waits on a channel with a 5 s timeout, never on a bare sleep.
- [ ] **Step 2:** `make test` → FAIL: `Terminals` not found.
- [ ] **Step 3: Implement.** One `portable-pty` pair per agent; a reader thread forwards each `read` buffer as-is to the current sink (`Arc<Mutex<Box<dyn Fn(Vec<u8>) + Send>>>`, so a reused open swaps the sink to the new window's channel); a waiter thread reports `exit_message(code, last 512 bytes as lossy text)` and removes the entry. `term_open` gets the target from `server_target`, runs `"ssh"` with `ssh_args`, sends bytes as `InvokeResponseBody::Raw`, and emits `term-exit` on exit. `term_write` writes the UTF-8 bytes of `data`. In `lib.rs`'s run loop, `RunEvent::Exit` calls `state.terminals.close_all()`.
- [ ] **Step 4:** `make test` → PASS.
- [ ] **Step 5: Commit** `feat(app): pseudo-terminals for the agents, over the system ssh`.
