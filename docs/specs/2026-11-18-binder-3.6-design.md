# Binder 3.6: Agents states, sessions of your own, quieter menu bar

The owner asked for colored states that tell the truth, sessions they can make, rename and close like herdr, usage they
can see at a glance, equal cards on Server, and a better menu bar icon that shows only while work is in progress.

## States

tmux reports a pane's shell (`bash`), which runs Claude Code or `docker exec` as its child, so every session read as
Exited. The state script now reads the shell's first child (`ps -o comm= --ppid`), and falls back to tmux's command
when there is none. Colors: Working green, Waiting yellow, Exited red, Idle gray, Off a hollow dot. When the server
can't be read, every session shows Error in red.

## Sessions

- New session: a name, a server folder (default `~/code/<slug>`), and Add to Projects. The folder is made if it isn't
  there. Without Add to Projects the session is kept in `config.toml` (`agents`); with it, Binder makes a project whose
  agent folder is that folder.
- Rename: from the terminal's header or by double-clicking a row. Names are kept in `agent_names` by tmux session and
  used by notifications too. A blank name goes back to the default.
- Close asks once, then ends the tmux session. Claude Code and Ollama stay listed as Off; a project's session leaves the
  list; a made session is forgotten.
- Any other `binder-*` session running on the server (the old `binder-qwen`) is listed and can be attached or closed.

## Usage

The header shows a bar per day of the last seven local days, today's brightest, then the 5 hour, today and 7 day sums.

## Server

The five cards stretch to the same height, and a pressed card shows a brighter border instead of a ring.

## Menu bar

The icon is the in progress mark: a ring with its right half filled. It shows only while a task is in progress or a
pomodoro runs, and its menu lists the tasks in progress first.
