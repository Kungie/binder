# Binder 3.12: Binder VPN for friends

## Why

The owner's VPS exit nodes make a small VPN. Friends should be able to use it with a user name and a password,
without a Tailscale account of their own and without seeing anything else on the owner's tailnet.

## Approaches

- **Tailscale plus our own sign-in (picked).** The friend installs the free Tailscale app. Binder VPN asks for a
  user name and a password, a small service on the home server checks them and asks Tailscale's API for a one-time
  key tagged `tag:friend`, and the friend's Tailscale signs in to the owner's tailnet with it. The owner's policy lets
  `tag:friend` reach the internet through exit nodes and nothing else. Tailscale makes the tunnel, so no Network
  Extension (which needs a paid Apple developer account) is needed.
- Our own WireGuard: no Tailscale, but the app would need an administrator password on every connect and every VPS
  its own setup.
- Headscale: friends fully apart, but every exit node would have to join a second network.

## Parts

### The sign-in service (`vpn/server/`)

- One Python 3 file, standard library only, in a `python:3.13-alpine` container. It runs as the `vpn` service of the
  site's compose project (`~/sites/binder-site`), and Caddy sends `/vpn/api/*` to it, so it is at
  `https://binder.erenkahraman.dev/vpn/api/` through the site's tunnel with no new DNS record.
- Data in a volume: `users.json` (name, scrypt hash with its salt, created, last sign-in) and `oauth.json`
  (Tailscale OAuth client id and secret), both mode 0600.
- `POST /vpn/api/login` with `{"user","password"}`: on a match, a Tailscale auth key (one use, preauthorized, not
  ephemeral, tag `tag:friend`, 10 minutes) and the host name `friend-<user>`. Wrong answers are one message,
  "Wrong user name or password.". After 5 failures in 15 minutes from an address (`Cf-Connecting-Ip`) or for a user,
  it refuses for the rest of the window.
- `GET /vpn/api/health`: whether the OAuth client is set.
- Command line for Binder, run with `docker compose exec -T vpn`: `users` (JSON list), `add <name>`,
  `password <name>` (password on stdin), `remove <name>` (also deletes the user's tagged devices from the tailnet:
  host name `friend-<name>` or `friend-<name>-<n>`), `oauth` (id and secret on stdin, two lines), `status`.
- Names are 1 to 32 of `a-z 0-9 -`, starting with a letter or digit. Passwords are at least 8 characters.

### Friends in Binder

The VPN screen gets a Friends panel: the service's state (not reachable, OAuth client missing, ready), the list
(name, created, last sign-in), Add (name and password), Reset password, Remove (asks first). A Set up form takes the
OAuth client id and secret. Everything runs over the server's SSH (`friends.rs` in the core, every value quoted,
secrets on stdin), never through the public address.

### Binder VPN (`vpn/app/`)

- A Tauri app with no Dock icon and no window until needed: a menu bar icon and a small sign-in window.
- Menu: the state (Off, or On and the city), Turn on or Turn off, the regions (every exit node the tailnet offers,
  named by city from its DERP region), Signed in as the user, Sign out, Quit.
- Sign in: `/usr/bin/curl` posts to the service (password on stdin), then
  `tailscale login --auth-key=file:<temp file> --hostname=<host>` adds a Tailscale profile, so the friend's own
  tailnet stays as a second profile. The profile id is kept in the app's data folder.
- Turn on: switches to that profile if another is in use, then
  `tailscale up --reset --hostname=<host> --exit-node=<ip> --exit-node-allow-lan-access`. Turn off:
  `tailscale set --exit-node=`. Sign out: `tailscale logout` on that profile.
- Tailscale missing, or never opened (its VPN configuration not allowed yet), shows what to do.
- The icon: the mascot inside a shield, so it reads as Binder and as a VPN; the menu bar icon is the same shape as
  a template, filled while on.
- No updater in this first version.

### The owner's part (in Tailscale's admin console, not done by Binder)

- Policy: `"tagOwners": {"tag:friend": ["autogroup:admin"]}` and a grant from `tag:friend` to
  `autogroup:internet` only; the default allow-all rule must start from `autogroup:member` instead of `*`, or
  friends would reach the owner's devices.
- An OAuth client with the `auth_keys` and `devices:core` write scopes and the `tag:friend` tag, given to Binder's
  Set up form.
