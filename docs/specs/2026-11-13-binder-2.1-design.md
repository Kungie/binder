# Binder 2.1: projects from GitHub, a task board, colour and Cloud

Status: draft, waiting for the owner's review. Builds on `2026-11-13-binder-2-design.md` (the 2.0 spec), which still holds wherever this one is silent. Where they disagree, this one wins.

## Why

The owner used 2.0 and found four things wrong:

1. **It looks unfinished.** "Black and white" meant mostly black and white, not only two colours. The screens feel loose and spread out.
2. **Projects are empty.** Adding every repo by hand is a chore when they all live on GitHub.
3. **The task table isn't the task manager the owner wants.** The owner wants a board like Roma (roma.app): status columns of soft cards with a two-line note and chips under it.
4. **The owner has files to keep at home.** Large files too, reachable from the owner's phone, stored on the home server.

After 2.1 ships, the owner and Claude map the home server's file tree together and clean it up. That is a session, not part of this spec, except that Cloud's folder must be easy to move once the disk layout changes.

## Goals

- Every GitHub repo of the owner shows up as a project without typing, and stays in sync.
- Projects that aren't on GitHub can still be added by hand.
- Tasks open on a board by default: columns by status, cards that read at a glance, drag to change status.
- The app looks finished: tight spacing, softer cards, a few meaningful colours.
- A Cloud screen: a small file manager over a folder on the home server, which the phone reaches too.

## Non-goals

- Scanning local folders for repos. GitHub is the source for now.
- Issues, pull requests or CI from GitHub. A project shows the repo, not its traffic.
- A light theme, themes or user-chosen colours.
- File previews, sharing links, sync clients or versioning in Cloud.
- Making Binder the only way into Cloud. Finder and the phone's Files app reach it directly.

## Anti-goals

- Colour as decoration. Every colour must mean something (a status, an urgency, a project), and screens stay mostly black and white.
- Losing the keyboard-first table. The list view stays for fast work.
- Binder storing a GitHub token or a Samba password. It uses `gh`'s own login and the Keychain entry macOS keeps for the share.
- A delete in Cloud that can't be undone by mistake.

## Approaches considered

**Projects.**
- (a) Scan a local folder for repos.
- (b) GitHub only.
- (c) Both.

The owner picked **GitHub, plus adding by hand**. A local folder can still be attached to a project for branch and change status.

**Cloud.**
- (A) An SMB share on the server, the same setup as the vault. Binder works on the mounted folder.
- (B) A File Browser container with a web UI, with Binder going over SSH.
- (C) SSH/SFTP only, with a third-party SFTP app on the phone.

The owner picked **A**: it reuses the vault's proven setup, the phone uses its built-in Files app, and large files move at network speed through the OS. B means two systems and another login. C needs a paid phone app and a hand-written transfer layer in Binder.

**Task board.** The owner asked for Roma's layout from a screenshot. The board sits beside the existing list view; it doesn't replace the data model.

## 1. Look

The 2.0 tokens stay. These change:

| Token | Hex | Use |
|---|---|---|
| bg | `#0B0B0C` | window background (off-black, so cards can lift off it) |
| panel | `#141416` | panels, board columns |
| card | `#1C1C1F` | board cards, inputs |
| raised | `#242428` | hover, selected, menus |
| line | `#26262A` | hairlines |

Colours, all used small (icons, dots, a chip's icon, a 2 px bar):

| Meaning | Hex |
|---|---|
| backlog, canceled | `#6B6B6B` (grey) |
| todo | `#D4D4D4` (light grey) |
| in progress | `#F2C94C` (yellow) |
| done | `#8B7CF6` (violet) |
| urgent priority, needs attention | `#F2994A` (orange) |
| high priority | `#E5E5E5` with the 2.0 bar icon |
| error, offline | `#EB5757` (red), only on the dot or icon |
| online, running | `#4CB782` (green), only on the dot |

- **Project colours:** each project gets one of 8 muted colours (`#5E6AD2`, `#26B5CE`, `#4CB782`, `#F2C94C`, `#F2994A`, `#EB5757`, `#B76EDB`, `#8D8D8D`), chosen from a hash of its name and changeable in the project's header. It shows as a small dot beside the project's name everywhere.
- **Shape:**
  - Cards and panels get a 10 px radius, controls 8 px.
  - Chips are pills: 24 px high, `card` fill, 1 px `line` border, a 12 px icon and 12 px text.
- **Density:**
  - Content gets a max width per screen (board: none; detail screens: 960 px), with 20 px gutters.
  - Rows and gaps follow an 8 px grid; nothing floats in empty space.
  - The sidebar is 208 px.
- **Type:** unchanged. Inter 13/12, weights 400 and 500, Geist Mono for numbers and ids.

## 2. Task board

- **Views:** the Tasks screen has a **Board** / **List** switch, remembered per view. Board is the default. List is the 2.0 table, unchanged apart from the new colours.
- **Columns:** Backlog, Todo, In progress and Done, left to right.
  - Each header has the status icon, name, count and a `+` that creates a task in that column.
  - Done shows only tasks finished in the last 7 days, with "Show all" at its foot.
  - Canceled tasks show only in the list.
- **Card:**
  - The title on one line, ellipsed.
  - The notes' first two lines, plain text with Markdown stripped, in `text-2`.
  - A row of chips:
    - status;
    - due date ("Today", "Tomorrow", a weekday within 7 days, else "12 Nov"), with a clock icon if a time is set, else a calendar icon;
    - project (colour dot and name);
    - assignee, shown only for the agent: "Claude" with the Claude mark.
  - An orange dot top right when the task needs attention (below).
  - Overdue dates show their chip text in orange.
- **Interaction:**
  - Drag a card to another column to set its status. Dropping on Done runs the 2.0 done-line prompt.
  - Dragging within a column reorders it, with the order saved per task.
  - Click opens the 2.0 side sheet. Keyboard: arrows move focus across cards and columns, Enter opens, `c` creates in the focused column.
- **Attention:** a task gets `attention = true` when its agent run ends (done, failed or lost). Opening the task clears it. The sidebar's Tasks count shows a small orange dot while any task needs attention.
- **Due times:** the due field takes an optional time ("Today 2 PM"). Stored as `due` (date) plus `due_time` (`HH:MM`, nullable).
- **Filters:** the existing views (All, Mine, Agent, per project) apply to the board as well. A search field above the board filters by title and notes.

## 3. Projects from GitHub

- **Source:** the `gh` CLI with the owner's own login. Binder runs `gh repo list <login> --limit 200 --json name,nameWithOwner,description,url,isPrivate,isArchived,pushedAt,primaryLanguage`, where the login comes from `gh api user`.
  - `gh` is found on the PATH or in `/opt/homebrew/bin` and `/usr/local/bin`.
  - Binder never reads or stores a token.
- **Sync:** on app start and with a **Sync** button on the Projects screen, off the main thread. A failed sync keeps the last list and shows the error in one line. Each repo maps to one project by `nameWithOwner`:
  - **New repo:** a new project.
    - Its name is the repo name and its prefix is derived as in 2.0.
    - It's `active` if pushed in the last 60 days, else `paused`.
  - **A hand-added project with the same name (case-insensitive) and no GitHub link:** linked to the repo instead of creating a second project.
  - **Known repo:** its description, URL, privacy and last push are updated. The owner's own edits (name, state, prefix, colour, local folder, agent folder) are never overwritten.
  - **Archived or gone from GitHub:** the project is marked archived and moved to the bottom, never deleted. A repo that comes back is unmarked.
- **Without `gh`, or not signed in:** the Projects screen says so in one line ("Sign in with `gh auth login` to bring in your GitHub repos.") and everything else works.
- **By hand:** **New project** stays as in 2.0, for projects with no repo on GitHub.
- **Project page:**
  - The header shows the GitHub link, private or public, the language and the last push.
  - "Local folder" (2.0's repo folder, renamed) is optional. When set, the git row (branch, changes, ahead and behind) shows as in 2.0.
- **Model:** a project gains `github` (`nameWithOwner`, unique, nullable), `url`, `description`, `private`, `pushed_at`, `archived` and `color`.

## 4. Cloud

- **On the server:**
  - A folder `/srv/cloud`, owned by the owner, mode 0750, shared by Samba as `[cloud]` with the vault's settings (SMB3 only, `smb encrypt = required`, the same `hosts allow`).
  - Both shares get `vfs objects = catia fruit streams_xattr` with `fruit:metadata = stream` and `fruit:resource = stream`, so macOS stops leaving `._` files.
  - Setup is a script the owner runs once with sudo, like the vault's.
  - The folder path is one line in the share config, so moving Cloud to a new disk later is: copy the data, change that line, reload Samba.
- **On the phone:** Files › Connect to Server › `smb://<the server's Tailscale address>/cloud`, signed in once as the owner. Works at home and away through Tailscale.
- **On the Mac:** Finder mounts `smb://<server>/cloud` at `/Volumes/cloud`, kept in Login Items like the vault.
- **In Binder:** a **Cloud** item in the sidebar, after Server, works on the mounted folder (path in Settings, default `/Volumes/cloud`). When it isn't mounted, it says "Cloud not connected" and offers **Connect**, which opens `cloud_share` so Finder mounts it (and asks for the password the first time).
  - **Browse:**
    - Breadcrumbs and a list of name, kind icon, size and modified date, sorted folders first, sortable by column.
    - Double-click enters a folder or opens a file with its default app.
    - A search field filters the current folder.
  - **Upload:**
    - Drop files or folders from Finder onto the list, or use **Upload**.
    - Copies run in the Rust side in 1 MB chunks, so a 20 GB file doesn't block anything.
    - A transfer tray at the bottom shows each file's progress, speed and time left, with cancel. A cancelled copy removes its partial file.
    - A name that already exists asks: replace, keep both (" 2" suffix) or skip.
  - **Download:** **Save to…** copies to a folder picked on the Mac, with the same tray.
  - **Manage:**
    - New folder and rename (inline).
    - Move by dragging onto a folder or a breadcrumb.
    - **Delete moves to `.trash/` at the share's root**, keeping the path. A **Trash** view lists it with restore and **Empty trash**, which asks first. Nothing is deleted outright.
  - **Space:** a bar in the header shows used and free space of the share's disk (from `statvfs` on the mount), so the owner sees when the server is full.
  - **Limits:** symlinks are shown but not followed out of the share. Hidden dotfiles stay hidden except through a "Show hidden" toggle; `.trash` is never listed as a folder.
- **Overview:** a small Cloud panel with used and free space and the last 3 changed files.

## 5. Sidebar

Overview, Tasks, Projects, Devices, Server, Cloud, Printer, then the active projects with their colour dots, then Settings.

## 6. Data

- Schema v3 migration:
  - `tasks`: add `attention`, `sort` and `due_time`.
  - `projects`: add the GitHub fields and `color`. The existing `repo` column becomes the local folder.
  - Earlier data keeps working.
- `config.toml` gains `cloud` (mount path, default `/Volumes/cloud`) and `cloud_share` (the share's URL for **Connect**, e.g. `smb://host/cloud`, set in Settings; never committed).

## 7. Testing

- **Core (Rust):**
  - GitHub sync against a fake `gh` (a trait, as with SSH): new, updated, archived and returned repos, and owner edits kept.
  - The v3 migration from a v2 database.
  - Cloud file operations on a temp folder: list, copy with progress and cancel, conflict choices, move to trash and restore, empty trash, refusing paths that leave the root.
- **UI (Vitest):**
  - The board renders columns and chips.
  - Drag to Done sets the status and shows the prompt.
  - The attention dot shows and clears.
  - Cloud's not-connected state, upload tray and delete-to-trash.
- **By hand:** the built app with the owner's GitHub and the real share, a large file upload, and the phone connecting.

## Left to the builder

- The drag and drop library (or native HTML drag events) and the exact animation.
- The Claude mark's drawing (a simple monochrome glyph is fine) and the other icons.
- Fixed column widths versus fill.
- The trash folder's layout, as long as restore puts a file back where it was.
