# Binder 2.3: Agents, and the server's power

Status: draft, waiting for the owner's review. Builds on the 2.0, 2.1 and 2.2 specs, which still hold wherever this one is silent. Where they disagree, this one wins. It replaces the "After 2.2" notes in the 2.2 spec.

## Why

The owner wants two chat agents on the home server, open side by side in Binder:

- **Claude Code**, for real server work, with full rights but a guard against the worst commands.
- **A small local model**, Qwen3 4B, for small jobs (log summaries, commit messages, done lines) so they cost no Claude tokens.

For now both are plain chats. Handing them tasks comes later. The owner also wants the Server screen to show how many watts the server draws.

## Goals

- An **Agents** screen with two live terminals side by side: Claude Code on the left, Qwen3 4B on the right, both running on the server.
- Both sessions outlive Binder: quitting Binder, the Mac sleeping or the network dropping never ends a chat. Opening Agents again picks up where it was.
- The terminals look like Binder.
- A **Power** box at the right end of the Server screen's top row.

## Non-goals

- Giving either agent tasks from Binder: no log summary, commit message or done-line buttons, and done lines stay on Haiku. Those come in a later release.
- Reaching the agents from the phone.
- More than one session per agent.
- Installing or updating Claude Code, Ollama, the model or tmux from Binder. The server is set up by hand (below).
- Power history or charts.

## Anti-goals

- Binder holding a key, a token or a password, or touching `~/.ssh`.
- Closing Binder or leaving the screen ending a session on the server.
- Global shortcuts (⌘K, `c`, arrows) firing while the owner types in a terminal.
- Opening a port for the model to anyone but the server itself.

## The server, as set up on 2026-11-14

Done by hand, recorded here so the builder knows what Binder can rely on. Binder only checks for it.

- **tmux** 3.5a from Debian.
- **Claude Code** 2.1.325, installed for the owner's user at `~/.local/bin/claude` by Anthropic's installer. The owner signs in once.
  - `~/.claude/settings.json` sets `permissions.defaultMode` to `bypassPermissions` and a `permissions.deny` list of 50 Bash rules: each of `rm -rf /`, `rm -rf /*`, `rm -rf ~`, `rm -rf /home`, `rm -rf /srv`, `rm -rf /srv/cloud`, `rm -rf /srv/vault`, `rm -r /srv/cloud`, `rm -r /srv/vault`, `mkfs`, `dd`, `wipefs`, `fdisk`, `parted`, `shred`, `reboot`, `shutdown`, `poweroff`, `halt`, `systemctl reboot`, `systemctl poweroff`, `chmod -R 777 /`, `docker system prune`, `docker volume rm` and `docker volume prune`, as `Bash(<cmd>:*)` and `Bash(sudo <cmd>:*)`.
  - The owner's user has sudo with a password. Claude can't type it, so a command that needs sudo fails and Claude hands it to the owner to run.
- **Ollama** 0.40.13 in Docker, `~/apps/ollama/docker-compose.yml`, container `ollama`, listening on `127.0.0.1:11434` only, models in `~/apps/ollama/models`, `OLLAMA_KEEP_ALIVE=30m`. Model `qwen3:4b` (2.5 GB), which writes about 4 tokens a second on the Pi 5.
- **Power** is readable without sudo through `vcgencmd pmic_read_adc`.

## Approaches considered

**Drawing the terminals.**
- (a) xterm.js in the window, fed by a pseudo-terminal in the Rust side that runs the Mac's own `ssh -tt` into `tmux`.
- (b) An SSH library inside Binder (russh) talking to the server directly.
- (c) Opening each chat in Terminal.app.

**Chosen: (a).** It keeps SSH where it already is (the system `ssh` with the owner's keys and `~/.ssh/config`, as the `Remote` trait does), so Binder holds no key. (b) means Binder loading and managing keys, which the anti-goals rule out. (c) can't put the two side by side in Binder.

**Keeping sessions alive.** `tmux` on the server, one named session per agent, created on first attach (`new-session -A`). The alternative, a long-lived process per chat started by Binder, dies with the SSH connection.

## 1. Agents screen

- **Sidebar:** Agents comes after Server: Overview, Tasks, Projects, Devices, Server, Agents, Cloud, Printer. Its icon is a 14 px terminal prompt (`>_`) in the sidebar's line style.
- **Layout:** the screen's usual 48 px header (title "Agents", the server target in mono `text-3`), then two panels side by side filling the rest of the window, split 50/50 with a 12 px gap and 20 px gutters. When the content area beside the sidebar is narrower than 900 px (a window under about 1110 px), they stack. (Builder's question, my call: the window's minimum is 960 px, so the rule is about the content area.)
- **Each panel:**
  - Header: the agent's name ("Claude Code", "Qwen3 4B"), a state dot (filled `ok` when connected, hollow `bad` ring when not), the tmux session name in mono `text-3`, and on the right a ghost **Reconnect** button shown only while disconnected.
  - Body: the terminal, filling the panel.
- **Terminal look:** background `panel`, text `text`, cursor `text` (block, blinking), selection `raised`, the 16 ANSI colours mapped onto Binder's palette (red `bad`, green `ok`, yellow `st-progress`, blue `#5E6AD2`, magenta `st-done`, cyan `#26B5CE`, white `text`, black `card`; bright variants a step lighter, the builder's call). Geist Mono 12 px, line height 1.3. 10 000 lines of scrollback in tmux.
- **Commands run on the server** (the session names are fixed):
  - Left: `tmux new-session -A -s binder-claude "bash -lc 'claude; exec bash -l'"`.
  - Right: `tmux new-session -A -s binder-qwen "bash -lc 'docker exec -it ollama ollama run qwen3:4b; exec bash -l'"`.
  - When the chat program exits, a login shell stays, so the session survives and the owner can start it again.
  - Before creating a session, Binder sets `history-limit 10000` globally (`tmux start-server \; set -g history-limit 10000 \; new-session -A …`), because tmux applies it only to new panes. Binder's two sessions are the only tmux use on the server, so a global setting is fine (my call).
  - On each attach it sets on that session: `status off` (no tmux bar), `mouse on` (the wheel scrolls back), `set-clipboard on`.
- **Connection:** the Rust side opens a pseudo-terminal running `ssh -tt -o BatchMode=yes -o ConnectTimeout=5 -o ServerAliveInterval=15 -o ServerAliveCountMax=2 <target> <command>`, with `<target>` from `config.server`, quoted as the `Remote` trait does.
  - Keystrokes go to it, and its output streams to xterm.js.
  - The window size follows the panel (xterm's fit addon), sent on every resize.
- **Lifetime:**
  - Both terminals connect the first time Agents opens and stay connected while Binder runs, also when another screen is shown, so coming back is instant.
  - Quitting Binder ends the local `ssh` processes only; the tmux sessions keep running.
  - A dropped connection marks the panel disconnected and keeps the last screen visible until **Reconnect**.
- **Keyboard:**
  - While a terminal has focus, every key goes to it, including `c`, arrows, Escape and Enter. Binder's own shortcuts stay quiet, except ⌘K, which still opens the palette.
  - Copying (my call, since tmux owns the mouse): a plain drag selects in tmux, which copies to the Mac clipboard through OSC 52 (xterm.js's clipboard addon). An Option-drag makes a native selection instead (`macOptionClickForcesSelection`), and ⌘C copies that. ⌘C never sends Ctrl-C; ⌘V pastes; Ctrl-C still interrupts.
  - Clicking a panel focuses its terminal. ⌘1 and ⌘2 also focus the left and right terminal while Agents is shown.
- **States:**
  - No server set: one line in place of the panels, "Set the home server in Settings to use Agents.", with a link to Settings.
  - Not reachable, or `tmux` missing on the server: the panel shows the error in one line (`ssh`'s own message, or "tmux isn't installed on the server.") with Reconnect.
  - Claude Code or Ollama missing: no special handling; the shell inside the session says so, and the owner fixes it on the server.

## 2. Power on the Server screen

- The status script gains one read: `echo --binder:power--; vcgencmd pmic_read_adc 2>/dev/null`.
- `parse_power` pairs each rail's current line (`<RAIL>_A current(n)=<x>A`) with its voltage line (`<RAIL>_V volt(n)=<y>V`) by rail name, and returns the sum of volts times amps in watts. Rails with only a voltage (`EXT5V_V`, `BATT_V`) are skipped. No lines, or no pairs, gives `None` (a server that isn't a Pi 5).
- `ServerStatus` gains `power_w: Option<f32>`.
- The Server screen's top row gets a fifth Metric at its right end: title "Power", value like `4.1 W` (one decimal), detail "Pi board". `None` reads "None", like Temperature.
- The PMIC sees the board's rails, not what USB devices and the NVMe drive draw from the 5 V input, so the number is the board's draw, a little under what the wall socket sees. The detail line says "Pi board" for that reason.

## 3. Code

- **Core (`crates/core`):** `server.rs` gets the power read, `parse_power` and the field. A small `agents.rs` builds the two `ssh` argument lists (session name, command, target) so they are testable without a terminal.
- **App (`app/src-tauri`):** `terminal.rs` owns the pseudo-terminals (the `portable-pty` crate or equivalent), keyed by agent:
  - `term_open(agent, cols, rows, channel)`: start, or return the running one; output goes to a Tauri `Channel` as bytes.
  - `term_write(agent, data)`, `term_resize(agent, cols, rows)`, `term_reconnect(agent)`.
  - All children are killed when the app quits.
- **Interface (`app/src`):** `screens/Agents.tsx`, `components/Terminal.tsx` (xterm.js with the fit addon, themed from the tokens), the sidebar item, the `Api` methods and their in-memory fake (an echo terminal that prints a welcome line, for tests and the browser preview), and the Power metric.

## 4. Testing

- **Core (Rust):**
  - `parse_power` against the real `pmic_read_adc` output from the Pi (Appendix A, kept as a fixture), giving 4.50 W (± 0.01).
  - An empty or garbled read gives `None`.
  - The status script still parses with the power section missing.
  - The two `ssh` argument lists, with a target that needs quoting.
- **UI (Vitest):**
  - Agents shows two panels with their names and session names.
  - No server set shows the Settings line.
  - A disconnected panel shows Reconnect.
  - With a terminal focused, `c` doesn't open New task, and ⌘K still opens the palette.
  - The Server screen shows the Power metric and "None" when absent.
- **By hand:**
  - The built app against the Pi: both chats connect, typing, scrolling, resizing and copy and paste work.
  - Quit Binder, reopen, and the chats are where they were.
  - Pull the network and Reconnect.
  - Power reads a sensible number (3 to 8 W).
