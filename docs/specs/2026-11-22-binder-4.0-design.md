# Binder 4.0: for anyone's setup, and safe

## Why

Binder grew around one owner's machines. 4.0 makes it something another developer can install and set up on their
own: a first-run setup, a short guide on each screen, steps where a screen still needs something, and Binder VPN
working with any server. It also closes the gaps a security pass found.

## Setup

- **First run.** While `onboarded` is false and no server is set, a dialog walks through: what each part needs,
  the home server (an SSH target, checked with `server_reachable` before it is saved), the vault folder, and `gh`
  (installed, signed in: `setup_checks`). Every step and the whole setup can be skipped. Settings › Setup runs it
  again.
- **Screen tips.** The first time a screen opens it shows two lines on what it is for and what it needs, until Got
  it (`tips_hidden`). Settings › Setup › Show tips again.
- **Setup steps.** A screen that can't work yet says how, in numbered steps with one action: Agents and Sites without
  a server, Sites with no sites, VPN without Tailscale, GitHub without `gh`.

## Binder VPN for any setup

- `vpn_dir` (default `binder-vpn`, a path under the server's home) is the service's compose folder, and
  `vpn_address` its public https address. Both are checked when saved.
- Friends › Install service writes `vpn/server.py`, `vpn/Dockerfile` and, when the folder has no compose file, a
  `docker-compose.yml` (port `127.0.0.1:8787`, read-only, no capabilities, no new privileges, the owner's uid), then
  runs `docker compose up -d --build vpn`. Update service does the same for a newer Binder.
- The Friends panel shows the setup in order: the service, the tailnet policy (copyable), the OAuth client, the
  public address (with Tailscale Funnel as the easy way) and whether it answers.
- Add friend fills in a 16 character password from the system's random source, and after adding shows an invite to
  copy: where to get Tailscale and Binder VPN, the server address, the user name and the password. Reset password
  does the same.
- The Binder VPN app asks for the server address too, remembers it, and only talks https to it.

## Security

- **Service.** Locks sign-ins after 5 failures from an address, 20 for a user and 200 in all within 15 minutes; the
  client address is Cloudflare's header, else the last `X-Forwarded-For` entry, else the socket. Bodies over 4 KB
  get 413, a negative or missing length 400, fields must be strings of bounded length. A client idle for 10 s is
  dropped and at most 32 are served at once. No server version in headers, `nosniff` and `no-store` on answers, no
  passwords or keys in logs. An OAuth client without Auth Keys and Devices Core write is refused before it is saved.
- **App.** Audit of the webview's permissions (no shell or opener from the page), HTML (no raw HTML; previews in a
  `sandbox=""` frame), shell commands (every value quoted) and curl calls (https only, `--`). Dependencies: `zip` 9,
  `rusqlite` 0.43 and `url` 2.5.9 for the advisories `cargo audit` found; the rest are Linux-only crates or the
  printer's pinned TLS, which doesn't use the affected WebPKI checks.

## Not now
