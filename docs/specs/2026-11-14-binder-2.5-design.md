# Binder 2.5: the agent works on its own, a watch on the server, and polish

Status: waiting for the owner's review. Builds on the 2.0 to 2.4 specs, which still hold wherever this one is silent. Where they disagree, this one wins.

Already done on this branch, outside this spec: the printer fix (Bambu printers send X.509 version 1 certificates, which webpki refused) and the site link moved from the README to the repo's website field.

## Why

- Tasks assigned to the agent wait until the owner presses Run. The owner wants the agent to pick them up by itself, and to save some for the night.
- A container on the server can stop or turn unhealthy without anyone noticing.
- The owner's display is 2K and Binder's text is small on it.
- Small gaps: the SD card's space shows nowhere, the Server boxes can't say what is using the load, memory or disk, and the DMG window is plain.

## Goals

1. **The agent picks up its tasks.** Every 10 minutes Binder starts the next task assigned to the agent, through the same background run the Run button starts today.
2. **Night tasks.** A task can be marked as a night task, shown with a purple moon. Night tasks wait in a queue on the server and run there one after another from 03:00, whether the Mac is awake or not.
3. **Binder keeps running when its window closes**, so the agent pick-up and the container watch go on. ⌘Q quits.
4. **A container watch.** Binder looks at the server's containers every minute and sends a Mac notification when one stops, restarts again and again, or turns unhealthy, and when it is back.
5. **Interface size** in Settings, for large displays.
6. **SD card space** next to the SSD's in Overview and Cloud, and both disks together in the Server screen's Disk box.
7. **What uses it:** pressing the Load, Memory or Disk box on the Server screen lists the biggest users, largest first.
8. **A DMG window that looks like Binder:** a dark background with the mascot and an arrow from Binder to Applications.

## Non-goals

- The agent typing into the open Claude Code terminal on the Agents screen. Runs stay separate from that chat.
- More than one agent run at a time, or choosing a time other than 03:00.
- Watching anything but Docker containers (services, disks, temperature).
- Notifications on the phone.
- A menu bar icon. The Dock icon stays and brings the window back.

## Anti-goals

- A task started twice, by the pick-up and the night queue or by two pick-ups.
- A failed run started again and again on its own.
- A flood of notifications: one when a problem starts, one when it ends.
- Binder writing to the server's crontab without saying so in Settings, or leaving a line behind it can't remove.

## Approaches considered (decided with the owner)

- **How the agent gets tasks.** (a) Binder starts background runs on the server, as Run does today, chosen. (b) Binder types tasks into the open Claude Code terminal: rejected, it collides with the owner's own chat and Binder can't tell when a task is done.
- **Where night tasks wait.** (a) A queue on the server run by a timer there, chosen, since the Mac may sleep at 03:00. (b) Binder starts them at 03:00: needs the Mac awake and Binder open.
- **When the watch runs.** (a) Binder stays running in the background after its window closes, chosen. (b) Only while the window is open.
- **What the Server boxes sort.** (a) The biggest processes and folders, chosen. (b) Containers by their own CPU, memory and disk.

## 1. The agent picks up its tasks

- While Binder runs (window open or not), every 10 minutes and once 30 seconds after start, it looks for the next task that:
  - is assigned to the agent, in **Todo**, not a night task,
  - belongs to a project with an agent folder (`agent_dir`),
  - has never had a run.
- It takes the one with the highest priority, then the oldest, and starts a run in the project's agent folder with **edits only** access, as the Run button does. The task moves to In progress, and its run shows in the task as today.
- Only one run at a time: nothing starts while any run is still going, the owner's own included.
- A task whose run failed goes back to Todo, as today, and is not picked up again. The owner starts it again with Run.
- A switch in Settings › Claude Code, **Pick up agent tasks**, on by default. Off, nothing starts by itself.
- Without a server set, nothing happens.

## 2. Night tasks

- **Marking.** The task detail gets a **Night task** toggle beside Assignee. Turning it on also assigns the task to the agent. A night task shows a 12 px moon in the night colour, `#B76EDB`, on its card, its table row and its detail, and the task list can be filtered to night tasks.
- **The queue.** On every pick-up round, Binder makes the server's queue match the night tasks in Todo:
  - A night task not yet queued gets a queued run: Binder writes the prompt and the run's folder to `~/.binder-agent/night/<run>.job` and records the run as **queued**. The task shows `Tonight` until then.
  - A queued run whose task is no longer a night task, no longer in Todo, or deleted, is removed from the queue.
- **Running.** A script Binder puts at `~/.binder-agent/night.sh`, started by the owner's crontab at 03:00, runs the queued jobs one at a time, oldest first, each the same way a run starts today, so its log, exit code and process id land where Binder already reads them. It stops starting new jobs at 07:00 and leaves the rest for the next night.
- **Afterwards.** When Binder next looks, each night run is read like any other: success moves the task to Done, failure to Todo. A night task that ran is no longer a night task.
- **The crontab line.** Settings › Claude Code shows **Night tasks** with the line's state: `Runs at 03:00 on the server` or `Not set up`, with **Set up** and **Remove**. Set up adds one line marked `# binder-night` and writes `night.sh`; Remove takes that line out and leaves the rest of the crontab as it was. Nothing is queued while the line isn't there.

## 3. Running in the background

- Closing the window hides it; Binder keeps running with its Dock icon. Clicking the Dock icon shows the window again. ⌘Q and Quit in the Dock menu quit.
- The Agents' terminals stay connected while the window is hidden.

## 4. The container watch

- Every 60 seconds, with a server set, Binder reads the containers' states (the same read the Server screen does).
- A container counts as in trouble when it was running and is now stopped or dead, is restarting, or is unhealthy. A container that was already stopped when Binder started doesn't count.
- When a container enters trouble: a notification titled with its name, `<name> stopped`, `<name> keeps restarting` or `<name> is unhealthy`, with its status line as the body. When it leaves trouble: `<name> is running again`.
- If the server can't be reached three checks in a row: `Can't reach the server`. When it answers again: `The server is back`.
- Clicking a notification opens Binder on the Server screen.
- The first time, macOS asks whether Binder may send notifications.
- A switch in Settings › Home server, **Notify me about containers**, on by default.

## 5. Interface size

- A **Display** panel in Settings with **Interface size**: 100%, 110%, 125%, 150%. The whole window scales at once; the choice is kept in `config.toml` and applied at start.
- ⌘+ and ⌘- step through the sizes, ⌘0 goes back to 100%.

## 6. SD card space

- **Overview**, Cloud panel: under the current bar (now labelled `SSD`), a second bar labelled `SD card` with its free and total space. Without an SD card in Cloud, only the SSD bar shows.
- **Cloud screen**: the same two bars where the one bar is now, whatever folder is on screen.
- **Server screen**, Disk box: the SSD and the SD card added together, used of total, and the percent of that total. The detail line reads `412 of 1,163 GB, SSD and SD card`.

## 7. What uses it

- The Load, Memory and Disk boxes on the Server screen become buttons. Pressing one opens a panel under the top row with its list; pressing it again, or another box, closes or switches it.
  - **Load:** the 10 processes using the most CPU: name, CPU %, memory %.
  - **Memory:** the 10 processes using the most memory: name, memory in MB, memory %.
  - **Disk:** the 10 largest folders on the SSD and the SD card, two levels deep, with their sizes. Folders Binder can't read are left out. This one takes a few seconds and shows `Counting…` meanwhile.
- Lists are read when the box is pressed, not on every refresh.

## 8. The DMG window

- A 660 × 400 window, background `#0B0B0C` with a subtle line grid in `#141416`, the mascot above the middle, Binder's icon on the left, Applications on the right, and an arrow between them in `#6B6B6B`. A 2x image for Retina.
- The background is drawn once from an SVG in the repo and committed as PNG. `make release` lays the window out through Finder; the first time, macOS asks whether the terminal may control Finder.

## Left to the builder

- How the queue's `.job` files are laid out, as long as `night.sh` and Binder agree and every value reaching the shell goes through `remote::quote`.
- How the watch's state is kept between checks.
- How the DMG background is rendered to PNG.

## Calls I made (owner, please check)

- The pick-up runs every 10 minutes, one run at a time, edits-only access, highest priority first, and only tasks that never ran.
- Night tasks stop starting new jobs at 07:00.
- The moon's colour is `#B76EDB` (a project colour), since the done colour `#8B7CF6` is also purple.
- Both the pick-up and the container watch have switches in Settings, on by default.
- The watch sends a notification when a problem ends too, and after three missed checks for the server itself.
- Interface sizes 100, 110, 125 and 150%, with ⌘+ ⌘- ⌘0.
