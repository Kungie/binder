# Binder 3.11: VPN

The owner runs VPSes on the tailnet as exit nodes and will add more in other countries. A VPN screen turns the exit
node on and off, picks the region, draws where the traffic goes and shows how it is doing.

## Source

Tailscale on the Mac, as on Devices: `status --json` lists the exit nodes (`ExitNodeOption`), the one in use
(`ExitNode`), each one's home DERP region (`Relay`) and bytes in and out (`RxBytes`, `TxBytes`, counted since
tailscaled started). On and off are `tailscale set --exit-node=<Tailscale address>` and `--exit-node=`; Binder only
runs them when the owner presses the switch or picks a region. Nothing goes to any other service.

## Regions

Each exit node is a region. Its place comes from its DERP region code (a table of Tailscale's regions with city,
country and coordinates), which is the nearest relay, so the owner can pick the right city from the same table;
picks are kept in `vpn_regions` (by host name). The last exit node used is `vpn_last`, so the switch turns on the
same one.

## Screen

VPN sits under Devices. The left side is a globe drawn in SVG: latitude and longitude lines, a dot for this Mac at
its own DERP region and one per exit node, turned so both ends show. While on, an arc runs from the Mac to the exit
node with a moving dash and the exit node pulses; off, the arc fades. Reduced motion stops the animation. The right
side has the switch (On, Off, or Connecting while Tailscale catches up), the regions list (name, city, online,
ping), and statistics for the exit node in use: ping and route (direct or through a relay), live speed down and up
(from the byte counters every 2 s) with a minute of history, total traffic, and how long it has been on since
Binder saw it turn on.

## Left out

The public address of the exit node (the Mac's Tailscale doesn't report it) and allowing the local network while
on.
