# Binder 2.2: fixes from first use

Status: draft, waiting for the owner's review. Builds on the 2.0 and 2.1 specs, which still hold wherever this one is silent. Where they disagree, this one wins.

## Why

The owner installed 2.1 and sent five things after the first day:

1. Projects deleted in Binder come back from GitHub on the next start.
2. Cloud is too weak to be a file manager: folder uploads crawl, and opening a zip froze, with no right-click menu.
3. Task priority shows nowhere that matters.
4. The Tasks header has a tab per project, which the owner doesn't want.
5. The Claude Code hooks never wrote anything. The owner wants each session's decisions in a daily file in the project's folder in the vault, and the important ones in Overview's "Done today".

## What we found

- **Zip freeze.** `cloud_open` hands the file to the Mac's default app. For `Github repos old.zip` (224 MB, 41,598 files) that is Archive Utility, which unpacks it file by file onto the SMB share next to the zip. It wrote 517 files in six minutes, then stalled, and left `.ArchiveServiceTemp…` in the folder. Binder itself never blocked.
- **Slow uploads.** SMB pays several round trips per file, so folders full of small files (a `node_modules` is about 1,600 files of 10 KB) take minutes. The same 1,600 files sent as one `tar` stream over SSH took 1.3 s. The server has `tar`, `unzip`, `zip` and `7z`.
- **Leftovers.** Quitting Binder during an upload leaves `.binder-partial-*` folders behind. They are hidden, so nobody ever cleans them up.
- **Hooks.** They are installed, but no session ever matched a project. A session's folder has to sit inside a project's "Local folder", and only one of the 15 projects has one; the GitHub projects have none. The hooks also run `binder-cli` from the build folder instead of `/Applications/Binder.app`.
- **Priority.** The list view has a small grey bar icon. The board, which is the default view, and the new task form show nothing.

## Goals

- A deleted GitHub project stays deleted, and can be brought back.
- Cloud works like a small Finder: a right-click menu, multi-select, clipboard, Quick Look, zips. Folder uploads take seconds, not minutes.
- Priority reads at a glance on every task surface.
- The Tasks header shows All, Mine and Agent only.
- Claude Code sessions land in the vault every day without setup, and Overview shows what happened today.

## Non-goals

- Skipping `node_modules` or other folders on upload. The owner wants everything copied, made fast.
- Pasting files copied in Finder into Cloud with ⌘V. Dropping them on the window already works.
- Archive formats other than zip (`.tar.gz` and `.7z` can come later).
- A native macOS context menu.
- Rewriting anything in `~/.claude/settings.json` other than Binder's own three hook entries.

## Anti-goals

- Any Cloud action that deletes outright, writes outside the share's root, or runs while the share isn't mounted.
- Shell commands built from paths without quoting.
- Losing a done line: what can't reach the vault waits in the database as in 2.1.
- A hook that slows Claude Code down or prints anything.

## Approaches

**Fast Cloud operations.**
- (a) Keep everything on SMB and copy in parallel.
- (b) Run bulk work on the server over SSH: `tar` streams for folders, `cp -a`, `unzip` and `zip` in place.
- (c) Skip regenerable folders (`node_modules`, build output) on SMB.

The owner picked **(b) with everything included**. Parallel SMB still pays per file, and skipping loses files the owner wanted. SMB stays as the fallback when SSH isn't set or fails, and for single files, where it already runs at network speed.

**Opening a zip.** The owner picked **extract on the server**, not handing it to Archive Utility and not asking each time.

**Context menu.** The owner picked **Binder's own menu** in React over the native macOS menu: it matches the app, works in the browser preview, and can be tested.

**Daily done.** Options were a `Daily/` folder in a per-project folder, daily files beside a note that stays where it is, or day headings in the one note. The owner picked **a folder per project with `Daily/`**.

**Hook path.** The owner agreed that Binder fixes its own three hook entries at start when they point to the wrong `binder-cli`.

## 1. GitHub projects stay deleted

- Deleting a project that has a GitHub link adds the repo to a new `hidden_repos` table (`github_id`, `name_with_owner`, `hidden_at`). Sync skips a repo whose id matches, or, for a row without an id, whose `nameWithOwner` matches (case-insensitive). A hidden repo is never linked by name to a hand-added project either.
- The delete prompt says so: "Delete binder? Its tasks stay, without a project. The note stays in the vault. Sync won't bring the repo back."
- **Bring back:** under the Projects list, a collapsed "Hidden from GitHub (2)" row. Opened, it lists each repo's `nameWithOwner` with **Bring back**, which removes the row and runs a sync, so the project returns as new (the old one's tasks stay without a project).
- Schema v5 adds the table. Deleting a hand-added project changes nothing.

## 2. Cloud as a file manager

### Selection and keys

- Click selects one; ⌘-click toggles; ⇧-click selects a range; ⌘A selects all; Esc clears. Arrows move, ⇧-arrows extend.
- Every action below works on the whole selection. Double-click or ⌘↓ opens; Enter renames (one item); Space shows Quick Look; ⌘C, ⌘X, ⌘V copy, cut and paste; ⌘D duplicates; ⌘⌫ moves to trash; ⇧⌘N makes a new folder; ⌘I shows info.

### Right-click menu

Right-click on an item selects it (unless it's already part of the selection) and opens the menu at the pointer. Right-click on empty space opens the folder's menu. Items that don't apply are hidden, not greyed. Each item shows its shortcut in `text-3`.

On items:

```
Open                        ⌘↓
Open with              ›   (apps that can open it, then "Other…")
Quick Look              Space
─────────────
Rename                     ↩
Duplicate                  ⌘D
Copy                       ⌘C
Cut                        ⌘X
Move to…
Save to…
─────────────
Compress "name" / Compress 3 items
Extract here                       (only .zip)
─────────────
Copy path
Get info                   ⌘I
─────────────
Move to trash              ⌘⌫
```

On empty space: New folder, Paste (when the clipboard has items), Upload…, Show hidden.

- The menu is a `raised` panel, 8 px radius, 1 px `line-strong` border, rows 28 px at 12 px text. Arrow keys move, Enter picks, Esc closes. It stays inside the window.
- **Open:** a folder enters it; a `.zip` extracts here (below); any other file opens in its default app as in 2.1.
- **Open with:** the apps Launch Services lists for the file, default first; "Other…" picks an app in `/Applications`. Opens with `open -a`.
- **Quick Look:** `qlmanage -p` on the file. Space again, or Esc in the preview, closes it.
- **Copy / Cut / Paste:** Binder's own clipboard of Cloud paths, kept while the app runs. Paste into the folder on screen or the folder right-clicked. Cut then paste is a move. Pasting onto an existing name asks the 2.1 question (replace, keep both, skip). Copies run in the transfer tray.
- **Duplicate:** a copy beside it, named as Finder does (`name copy.ext`, then `name copy 2.ext`).
- **Move to…:** a small folder picker of Cloud's tree. Dragging onto a folder or breadcrumb still works.
- **Save to…:** the 2.1 download, for the whole selection.
- **Compress:** one item makes `name.zip`; several make `Archive.zip`. Free names as for Duplicate.
- **Extract here:** a folder named after the zip, free name if taken.
- **Copy path:** the Mac path (`/Volumes/cloud/…`) to the clipboard.
- **Get info:** a side sheet with name, kind, size (a folder's total and item count, counted on the server), modified, created and the Mac path.
- **Move to trash:** the 2.1 trash with its undo toast, for the selection.

### Fast path over SSH

- `config.toml` gains `cloud_remote`, the share's folder on the server (default `/srv/cloud`), set in Settings next to the share address.
- **When it's used:** for folder uploads and downloads, copy and duplicate inside Cloud, compress, extract and folder sizes, whenever a server is set and a check passes (below). Single-file uploads and downloads, moves and renames stay on SMB.
- **The check:** before the first fast operation in a session, Binder writes a random token to `.binder-check` at the share's root through SMB, reads it back over SSH at `cloud_remote`, and removes it. If they don't match, or SSH fails, the fast path is off until the next app start and everything uses SMB. Settings shows which path is in use.
- **Paths:** every relative path is checked with 2.1's `resolve` on the mount first, then joined to `cloud_remote` and quoted with `quote`. Nothing else from the interface reaches a shell.
- **Folder upload:** `tar -cf - -C <parent> <name>` on the Mac, piped into `ssh <server> sh -c 'mkdir <partial> && tar -xf - -C <partial>'`, then a rename to the final name with 2.1's conflict rules. Progress counts the bytes sent against the folder's size.
- **Folder download:** the same, reversed, into a partial folder on the Mac.
- **Copy inside Cloud:** `cp -a` into a partial name, then the rename.
- **Extract:** `unzip` into a partial folder, then the rename. Progress counts the files unzip reports against `unzip -Z1 | wc -l`. unzip already refuses entries that leave the folder; Binder also refuses a zip if any entry name starts with `/` or holds `..`.
- **Compress:** `zip -r -y` (links stay links) into a partial name, then the rename. Progress counts files against the item count.
- Every one of these runs in the transfer tray with cancel. Cancel kills the SSH process and removes the partial on the server.
- **Without the fast path:** copy, duplicate and download fall back to 2.1's chunked SMB copy. Compress and extract fall back to the `zip` crate on the Mac, reading and writing through the mount, with the same partial names and progress.

### Drag out to Finder

- Rows start a native drag through `tauri-plugin-drag` with the selection's Mac paths. Dropped in Finder or another app, it copies, as from any mounted disk.
- Dropped back on Binder's window, Tauri reports a file drop with the paths and the pointer position. Paths inside the share are a move into the folder under the pointer (or the folder on screen); paths from elsewhere are an upload, as in 2.1.
- If the plugin can't start a drag from a webview row on this macOS, drag-out is left out of 2.2 and in-app drag stays as in 2.1. The builder says so before cutting it.

### Leftovers

- When Cloud opens, `.binder-partial-*` items whose process is no longer running are moved to the trash, where they show as "Unfinished upload: name". Emptying the trash removes them. Partials of copies still running are left alone.

### Unchanged

The mount check, root containment, trash with `.origin`, the conflict prompt and the space bar all stay as in 2.1.

## 4. Tasks header

The header keeps All, Mine and Agent. The per-project tabs go. A project's tasks are still on its project page. If the view is a project view when Tasks opens (from the sidebar or the palette), it switches to All.

## 5. Claude Code, connected

### Which project a session belongs to

`project_for` tries, in order:

1. A project whose Local folder holds the session's folder (2.1).
2. The git repository the folder is in: its `origin` remote is parsed to `owner/name` (https and ssh forms) and matched to a project's GitHub link, case-insensitive.
3. The repository folder's name, matched to a project's name, case-insensitive.

A match by 2 or 3 sets that project's Local folder to the repository's root when it has none, so the project page shows its git status too. The owner's own Local folder is never overwritten.

### Vault layout

```
Projects/
  binder/
    binder.md            the project note (made from the 2.0 template)
    Daily/
      2026-11-13.md
```

- A project's note moves from `Projects/<name>.md` to `Projects/<name>/<name>.md` the first time Binder touches it, if the new path is free. The note's text is unchanged, including its old `## Done` lines. Obsidian keeps its links by name.
- A daily file is made on the first line of the day:

  ```
  ---
  project: "[[binder]]"
  date: 2026-11-13
  ---

  # binder, 13 November 2026

  - 14:32 · Deleted GitHub projects are remembered and sync skips them.
  ```

- Every done line goes there as `- HH:MM · text`: the lines Claude's summary picks and the line typed when a task is marked done. Binder never edits a line after writing it, and only appends.
- When the vault isn't mounted, lines wait in `pending_done` with their date and time, as in 2.1.

### Hooks

- At start, if Settings › Claude Code is on and the app runs from an installed bundle (not a dev build), Binder checks that its three hook entries run this bundle's `binder-cli`. If not, it rewrites only those three entries, as `hooks::install` does today.
- Settings shows the hook state in one line: on, and the time of the last line written.

### Done today

- Overview's "Done today" reads today's daily files: each line with its time and project (colour dot and name), newest first.
- The model already picks at most three key decisions per summary, so every line counts as important. The panel shows the newest 8, with "Show all" when there are more.
- The project page's Done list reads its daily files, newest first, followed by the old `## Done` lines from the note.
