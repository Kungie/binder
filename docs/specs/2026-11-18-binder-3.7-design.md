# Binder 3.7: the tailnet on Devices

The owner asked for Tailscale on Devices: every device listed by itself, alerts, ping, Taildrop and SSH.

## Source

The Mac's Tailscale app, through its command line (`/Applications/Tailscale.app/Contents/MacOS/Tailscale`, or
`tailscale` in Homebrew's paths): `status --json`, `ping -c 1 --timeout 3s --until-direct=false <ip>` and
`file cp -- <paths> <host>:`. No login or API key. Without the app, Devices says so and the rest of the screen works.

## Devices

A Tailscale panel above the owner's own devices lists this Mac first, then the others by name: system, Tailscale
address, online or offline (with when it was last seen), the last ping and its route (green direct, yellow through a
DERP relay), a bar per ping of the last day, and the key: red when expired, yellow when it expires within 7 days.
Send file opens the file dialog and sends with Taildrop to devices that accept files. SSH asks for the target, the
server's user at the device's MagicDNS name by default, and opens a login shell (`ssh -tt`, keys only, no tmux) in a
terminal under the panel; Close ends it here.

## Watching

Once a minute Binder reads the status. A computer (not a phone or tablet, which sleep all day) going offline or coming
back sends a notification, as does a key that expired or expires within a week (once a day per device). Both follow
the same switch as the server's container alerts (`watch`). Every 5 minutes it pings the online devices and keeps the
last 24 hours in memory; a restart starts the history again.
